# Live trip and financial workflows

Owner-selected DEC-04/11–17/20 rules are recorded in the decision log. M5/M6 backend implementation verified 22 October 2026 with 211 unit/HTTP/PostgreSQL checks, clean/repeated migration deployment, build, typecheck and lint. Both web portals pass real desktop/mobile trip-to-statement journeys; native driver calls verify execution/earnings, while Flutter/device integration remains separate. See [evidence](../docs/verification/live-financial-workflows/README.md).

Assignment/reassignment checks enabled active drivers with completed password setup, preserves start/expenses, invalidates confirmation and revokes former-driver operational access. Trip reads include safe driver contact. Start, expense writes and closure require the current active driver; historical reports/earnings remain payroll-owner scoped even if their profile becomes inactive. All versioned writes use strong trip ETags; command replay rechecks authorization first. Expense confirmation derives a server replay key from the actor-scoped trip/version/body because that contract declares If-Match only.

Expenses must be positive and remain outside payouts. Add/edit/delete advance the trip aggregate version and clear confirmation in a database trigger. Confirmation must cover the complete current list; empty confirmation is explicit. Receipt uploads remain a separate private-media extension: non-null receipt IDs are rejected with RECEIPT_UPLOAD_UNAVAILABLE rather than accepting unscoped assets. Optional selfies are not a start requirement.

Code reveal is an explicitly requested partner-only company-scoped read with fresh authorization, browser origin/CSRF protection, no replay/cache persistence and metadata-only audit. Driver checks use keyed constant-time validation. Wrong attempts return a durable rejected command: same-key retries count once and failures survive financial rollback. Five failures lock for 15 minutes. Attempt state does not advance the operational ETag. No reveal/attempt material enters audit, ordinary reads or email.

Closure locks company then trip, selects the closure-effective rate, calculates exact BigInt paise with half-up driver rounding and company remainder, and commits trip, completed assignment, payroll, immutable report, one wallet credit, balance, audit and replay together. Permanent trip uniqueness survives command expiry. A retry after closure returns the recorded result to the active credited driver without checking a consumed code or adding money. Database checks enforce immutable closed history, half-up driver rounding, closure/payroll timestamp equality, the rate interval effective at closure, closed-trip financial references and ledger/balance reconciliation. External payment metadata is audited and never recalculates history. No withdrawals, reversals, adjustment or payment gateway is added.

Statements use actual closure/payroll instants in completed Asia/Kolkata calendar months, exclusive ends and exact copied totals. Company/month uniqueness, creator-only draft regeneration, version-checked submission, frozen lines, explicit creator plus one distinct admin approval and publication are enforced transactionally and in SQL. Publication stores a company-contact email intent atomically; failure to enqueue rolls back publication. Partners see only published own-company statements. Existing capture worker accepts statement publication; production email remains deferred.

Relevant suites: tests/finance.test.ts and tests/integration/trip-finances.integration.test.ts. PostgreSQL cases use real synthetic driver activation prerequisites and transactions, not relaxed database guards. Historical monthly fixtures insert complete synthetic immutable records in one transaction; the production API never exposes clock overrides or backdating.

Statement command responses retain an explicit 4 MiB canonical JSON replay bound (6 MiB PostgreSQL JSONB text bound, including whitespace) to support complete monthly line sets; the normal 48 KiB request/audit screening stays unchanged and credential/code screening still applies. Larger monthly datasets remain subject to the planned DEC-24 large-result/export design.

Custom SQL owns cross-domain scalar foreign keys, deferred consistency checks and immutability triggers. Prisma schema diff therefore reports the deliberately unmapped foreign keys; do not apply an autogenerated diff that drops them. Modeled relations explicitly match the SQL no-action update behavior. Reviewed migrations remain the executable schema source.
